【一】编译方法（必须用 XeLaTeX，且要跑两遍）

本文件使用了 ctex 中文宏包、TikZ 绘图与 listings 代码排版，
必须用 XeLaTeX 引擎编译；并且要连续编译两遍
（第一遍生成引用信息，第二遍图表编号才正确）。

方式一：命令行（本机已装 TeX Live 2024，可直接用）
    xelatex adc-report.tex
    xelatex adc-report.tex

方式二：Overleaf
  1) 把 adc-report.tex 上传到项目里；
  2) 左上角 Menu → Compiler 选 XeLaTeX；
  3) 点击 Recompile（Overleaf 会自动处理两遍的问题）。

方式三：TeXstudio / VS Code + LaTeX Workshop
  引擎选 XeLaTeX，连续编译两遍即可。

注意：只跑一遍时，正文里的“图 11、表 9”等编号可能对不上，
      再编译一遍就正常了。

【五】图是怎么画出来的
--------------------------------------------------------
14 张图全部用 TikZ 写在 adc-report.tex 内部，是矢量图，放大不糊；
改图内文字等于改代码里对应的中文，不需要外部图片。
若想换成别的画图工具（如 StarUML / Visio / MySQL Workbench），
把对应的 tikzpicture 环境整体替换成 \includegraphics{你的图片} 即可。

【七】小提示
--------------------------------------------------------
· 数据字典与建表 SQL 中的字段名采用英文小写下划线命名（patient_id 这类），
  中文含义在数据字典的“中文含义”列与 SQL 的 COMMENT 里，两者一一对应。
· 愿景里的“取消率下降 25%”以及各处时间基数是合理假设值，
  若老师有具体口径，改 搜：度量指标的选取说明。
· 建表 SQL 按 MySQL 语法书写（AUTO_INCREMENT、COMMENT 等），
  可直接在 MySQL / MariaDB 中执行；执行顺序已按“被引用表先建”排好。
· UC-03 第 8 步的预约状态改写统一由 UC-05 执行，与 UC-02 业务规则第 6 条
  保持一致——这是刻意的设计，答辩时若被问到可以这样解释。
· 分析序列图与状态机图用的类名、状态值都与前面章节完全一致：
  预约状态 {待就诊 | 已就诊 | 未到诊 | 已取消}，
  结算单状态 {待出具 | 已出具 | 待支付 | 已结算}。
